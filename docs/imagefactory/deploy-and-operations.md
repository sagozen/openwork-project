# ImageFactory deploy and operations

ImageFactory is one Cloudflare Worker (`imagefactory-web`) at `https://imagefactory.zhst.app`, with D1
`imagefactory-web`, KV `SESSION`, R2 bucket `imagefactory-images`, the `EMAIL` send binding and three cron
triggers. Images are generated by fal.ai. Product notes are in
[`apps/imagefactory/README.md`](../../apps/imagefactory/README.md).

## 1. Provision (once)

```bash
npm run provision:imagefactory                                    # dry run: what exists, what would be created
node scripts/provision-app.mjs imagefactory --apply               # creates D1, KV and R2, writes the ids into wrangler.jsonc
```

Review the diff to `apps/imagefactory/wrangler.jsonc` and commit it: the deploy refuses uncommitted changes in
`apps/` and `packages/`. The custom domain `imagefactory.zhst.app` is declared in `wrangler.jsonc` and attached on
the first deploy; the zone must be on the same Cloudflare account. Enable Cloudflare Email for the
`imagefactory.zhst.app` sender domain, because sign-in links are sent through the `EMAIL` binding.

## 2. Secrets

Set from `apps/imagefactory`. Values are typed at the prompt and are never committed or echoed.

```bash
npx wrangler secret put BETTER_AUTH_SECRET     # at least 32 random characters: openssl rand -hex 32
npx wrangler secret put FAL_KEY                # fal.ai API key
npx wrangler secret put GOOGLE_CLIENT_ID       # optional, set with the next one or not at all
npx wrangler secret put GOOGLE_CLIENT_SECRET   # redirect URI https://imagefactory.zhst.app/api/auth/callback/google
```

`APP_ORIGIN`, `BETTER_AUTH_URL`, `ADMIN_EMAILS`, `EMAIL_FROM`, `EMAIL_PROVIDER` and `IMAGE_PUBLIC_BASE` are plain
variables in `wrangler.jsonc`. `ADMIN_EMAILS` lists the accounts that become admins the first time they open
`/admin`. Do not set `PAYMENTS_PROVIDER`: there are no packs and no checkout routes.

`BETTER_AUTH_SECRET` also signs the ten-minute links the image provider uses to fetch private brand references.
Rotating it signs everyone out and ends pending authorizations.

## 3. Check, deploy, smoke

```bash
npm run preflight:imagefactory     # lists exactly what is missing (resource ids, secrets, origin variables)
./deploy-cf.sh imagefactory        # gates, D1 backup + migrations, deploy, then scripts/smoke-imagefactory.sh
```

The script exports D1 before applying migrations (the first deploy has an empty database, so there is nothing to
back up) and prints the version id to roll back to. The smoke test is read-only. It checks health, the landing page
and security headers, both OAuth metadata documents, the `/mcp` 401 challenge for a missing token and a plain 401
for a bad API key, the REST 401, an unsigned provider callback, the 404s on the image hosts and the sign-in redirects.

## 4. Credits

Credits are granted by an admin only. Open `/admin/accounts/`, search the account's email, enter a positive
number and a reason under "Adjust credits". The ledger records the adjustment with your admin id. New accounts start
with 0 credits: a migration sets the free monthly allowance to 0 for this app, so sign-ups cannot spend your fal.ai
budget. You can raise "Free credits per month" in `/admin/settings/` later. No checkout page exists.

## 5. Day-to-day controls (`/admin/settings/`, admin role)

| Setting | Effect |
|---|---|
| Generation is on | Off refuses every generate and edit with "Image generation is paused". Reads still work. This is the kill switch. |
| Credits per megapixel (both models) | Applies to the next job. Jobs already reserved keep the price they were reserved at. |
| Most images per call, calls per minute | Per-account limits. |
| Free credits per month | New wallets and monthly resets. |
| Seconds a job waits for a worker | Past this a queued job goes to fal.ai. Default 45. |

Every change needs a reason and is written to the append-only audit log (`/admin/audit/`).

## 6. Crons and recovery

| Cron | Does |
|---|---|
| `*/5 * * * *` | Sweep. Moves worker-lane jobs that no worker is taking to fal.ai, finishes jobs whose webhook never arrived, fails jobs the provider lost, returns the credits of any job still open after 30 minutes (including one the provider finished but whose result cannot be read), and releases a finalizing claim abandoned for more than five minutes. |
| `0 * * * *` | Removes files of images deleted over 30 days ago, up to 200 objects per run. The public URL already stops at delete time. |
| `20 3 * * *` | Runs that same file removal, completes due account deletions, retries failed emails, and emails `ADMIN_EMAILS` a digest: images and jobs in 24 hours, failure rate, credits charged, and the fal.ai cost estimated from started megapixels. |

A job stuck in `/admin/jobs/` shows its state and age. The sweep acts on it within five minutes; nothing needs
to be run by hand. Settlement is a single database batch guarded by a per-attempt token, so a job is never
charged twice however the webhook, the in-tool wait and the sweep race.

To look at the sweep: `npx wrangler tail imagefactory-web --format json` and filter on `"evt":"sweep_cron"`,
`"evt":"hourly_cron"` or `"evt":"fal_webhook_failed"`.

## 7. Real-client verification (do after the first deploy)

Nothing here can be proven from tests alone; the tests cover the OAuth flow and tool calls against the app's own
code. Record the result of each row (and the date) in
[`connect-guide.md`](connect-guide.md) and as notes under `plans/261106-1950-imagefactory-mcp-mvp1/reports/`.

| Client | Check |
|---|---|
| claude.ai web | Add the connector, complete sign-in and consent, run `create_brand`, `generate_image` (preset pin) and `edit_image`. Does the inline preview show? |
| Claude Chrome extension | Same account. Generate a pin and check the URL works in Pinterest's "create pin from URL". |
| Claude Desktop | The connector appears from the account; repeat the generate check. |
| ChatGPT | Developer mode, add the MCP server, OAuth, `generate_image`. Is a markdown image or image block shown? |
| MCP Inspector | `npx @modelcontextprotocol/inspector` against `/mcp` with a key: tool list and schemas validate. |
| n8n, Make | HTTP call to `POST /api/v1/images/generate` with a key returns a URL; n8n's MCP Client node lists the tools. |
| Postiz | Create a post from an image URL returned by an n8n run. |

Also run `node scripts/imagefactory-fal-smoke.mjs` once (about $0.05). It prints real latency and file sizes. If
typical results exceed 750 KB the inline preview is skipped and clients show only the link; consider whether
WebP output is acceptable for your Pinterest and KDP use before changing the format.

## 8. Operations runbook

**Rotate the fal.ai key.** Create the new key in fal.ai, `npx wrangler secret put FAL_KEY`, run a generation, then
delete the old key. Wait a few minutes before deleting it: a job queued under the old key cannot be read back
once that key is gone. The sweep then fails such a job and returns its credits.

**Disconnect everyone (OAuth grants).** Export D1 first (`npx wrangler d1 export imagefactory-web --remote --output
backup.sql`), then run in one `wrangler d1 execute imagefactory-web --remote --command` call:

```sql
UPDATE agent_grants SET active = 0, generation = lower(hex(randomblob(16))), revoked_at = CAST(strftime('%s','now') AS INTEGER) * 1000;
DELETE FROM oauthAccessToken; DELETE FROM oauthRefreshToken; DELETE FROM oauthConsent;
```

The next call from every connector returns 401 and the client asks the user to sign in again. A single person can
disconnect an app on `/account`.

**Revoke one API key.** The owner revokes it on `/account`; an admin cannot see key values, only prefixes.

**Suspend an account.** `/admin/accounts/`, admin role. A suspended account is refused on `/mcp` and the REST API.

**Roll back.** `cd apps/imagefactory && npx wrangler rollback <version-id> --config dist/server/wrangler.json` (the
deploy script prints the version id). Migrations are additive; restore D1 from the exported backup only if a
migration itself is the problem.

**Back up D1 manually.** `npx wrangler d1 export imagefactory-web --remote --output <file>.sql`. Image files live in R2
and are not part of the export.

**Delete an account on request.** The owner can do it on `/account`; it completes after 30 days. The purge removes
the account's R2 prefixes and rows.

## 9. Worker lane (OpenClaw)

An agent in OpenClaw can make the images instead of fal.ai. It pulls jobs over outbound HTTPS, the same way the
TranscriptAnything transcriber does, and fal.ai stays on as the backup. Register the worker at `/admin/workers/`,
run `services/openclaw-worker` on the OpenClaw host, and read [`openclaw-worker.md`](openclaw-worker.md) for the
setup, the job contract, the fallback rules and troubleshooting. The worker API lives under
`/api/internal/worker/*` and accepts only `wkr_` tokens, so a leaked API key or session cannot lease jobs.

## 10. Cost model

Images made by a worker cost no provider fees and are priced in credits exactly like fal.ai images; the daily
digest lists them separately as `worker_images` and leaves them out of the fal.ai cost estimate.

fal.ai bills per started megapixel: $0.02 for text to image and $0.03 for edit. With one credit at one US cent and
the default 4 and 6 credits per megapixel, the credit value is twice the provider cost. The daily digest shows the
real numbers, so adjust `pricing.*` in `/admin/settings/` if the margin should change. fal.ai starts new accounts at
two concurrent jobs; extra requests wait in its queue and the tool reports the queue position.
